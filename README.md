# Designing-a-data-model

1. Проектирование архитектуры сущностей

Выполнена декомпозиция предметной области и спроектирована структура базы данных для системы барбершопа.

Реализовано обобщение (Generalization): Выделен абстрактный класс «Персона» для хранения общих атрибутов всех пользователей (логин, пароль, ФИО, телефон). Это позволяет избежать дублирования данных.

Спецификация сущностей: Разработаны детальные описания для дочерних и основных сущностей:

Участники: «Клиенты» и «Сотрудники» (наследуют данные от «Персоны» через внешний ключ).

Справочники: «Услуги», «Роли сотрудника» (Мастер/Менеджер).

Связующие сущности: «Услуги мастера» (связь многие-ко-многим между сотрудниками и услугами).

Операционные сущности: «Слоты обслуживания» (запись на прием), «Скидки», «Извещения».

2. Атрибутивный состав

Для каждой спроектированной сущности определен полный набор метаданных:

Идентификаторы: Первичные ключи (PK) и Внешние ключи (FK) для организации связей.

Типы данных: Определены форматы (строковые, числовые, дата/время) и ограничения длины.

Ограничения целостности: Указаны обязательность полей (Not Null) и значения по умолчанию (Default).

:* (Многие ко многим)* — реализовано через промежуточные таблицы (Мастер — Услуга).
